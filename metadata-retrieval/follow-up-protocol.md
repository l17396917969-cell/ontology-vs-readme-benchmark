# 第二轮 · 新问题和两域组合

首轮完成后写定这项补充实验，探索单入口关系导航与按业务域找文档的边界。保留首轮生成器、模型设置、排序函数、关系导航函数、K=6、执行与判分规则。用首轮未提问的 6 个业务域，设计 4 类新问题各 6 道，共 24 题。其中有带条件的客服工时、跨源历史净回款、两域之间的净回款差额，以及缺合作伙伴身份映射的问题。合计 96 次新模型调用。仍是合成数据和 4 类问题模板，24 是题目数量。

- 整份 README 为同一个 216 资产目录。
- BM25 与单入口关系导航使用原来的 6 张预算。
- 业务域路由先用问题中明写的业务域名匹配目录。把该域的所有 9 张说明交给模型，双域题交 18 张。该组输入较大，报告实际 token。相较严格的等资料量对照，这组回答是否存在朴素可行的 README 方案。
- 用独立 Python 运算计算单域变体答案。双域差额从两边独立计算的基础口径相减。没有写题者替检索器指路。

第二轮原定四组判分后，单入口关系组的 6 道跨域题都漏掉另一个域。补跑 24 次带参考资料的诊断。逐题保留全部预定资料，再按原 BM25 顺序补到 6 张。SQL 模型、预算和执行方式保持相同。这个条件知道出题时预定的资料，只用于检验检索覆盖对失败的解释。
