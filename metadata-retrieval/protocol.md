# 本体与 README 对照实验

这是合成企业数据上的受控实验。测试对象为只读问数。问题包括单模块查数、跨源关系、两版制度口径、分析宽表去重，以及缺失信息的拒答。问题与评分在 API 调用前写定。统计单位是题，重复数据快照用于核对 SQL 语义。

| 操作 | 比较条件 |
| --- | --- |
| 扩大可见知识范围 | 每题只给所属业务域的 9 张资产说明，或让系统面对 24 个域的 216 张说明。题目和底层 SQLite 表相同。 |
| 扩大业务数据量 | 每个域 24 或 240 笔订单，分别用两个随机种子。相同 SQL 在四个快照执行。 |
| 整份 README | 将范围内所有资产说明合并。固定顺序，扩大范围时混入其他域的相似术语、表和规则。 |
| README + 搜索 | 同一内容切为资产说明，BM25 排序，最多取 6 张。 |
| 结构化关系检索 | 用同一个 BM25 得分作种子，扩展类型化资产关系，最多取 6 张。模型看到的仍是同一份说明原文。 |
| 已知材料对照 | 直接给写题时预定的参考材料。只作诊断。 |
| README 链接等价核对 | 从已发表给模型的 Markdown 资产卡重新解析显式编号链接，用同一种遍历。比对每题所选材料及提示词是否逐字相同。这是程序等价性检查，无额外模型采样。 |

使用已有的 DeepSeek API 接入。每题每组使用无会话单轮请求，相同模型、系统提示、温度与输出预算。题目不要求猜测缺失内容。模型可交 SQL 或明确 abstain。SQL 统一在本地 SQLite 执行，无试错或查询反馈。一条 SQL 须通过四次结果比对，输出格式须齐全，缺失题须正确拒答。检索覆盖另计。观察 API 回报的输入输出 token、调用时间和 SQL 失败类型。

结构层是一个小型、带类型的领域及数据资产关系模型。结构组只使用其导航能力。README 携带同样的口径、字段、连接说明、显式链接。实验不涉及 OWL 推理。范围、文档数量、问题数、底层行数有各自的计量。没有真实企业数据、权限、写入、并发或运维成本。对照搜索是可核对的 BM25，不代表混合检索、重排或自助多轮系统的性能上限。
