# Benchmark · 从企业关系里发现未写明的风险

**结论**　README 可以支持发现新问题。在本次数据里，全文组从未标注风险的授权记录推出了职责分离失效。图路径的增益出现在另一层：在大量相似资料中，集中提供目标业务的可追溯关系，减少串用记录，并把发现落到具体证据。

## 三个样例

给模型的任务只说“审查这条产线的供货”“审查站点复产”“审查这笔付款的控制”。资料里只有对象、规则、记录和关系，三个隐患没有写成结论，也没有风险维度或预写检测函数供模型选。

| 样例 | 有风险 | 只改一条关系后的对照 | 同一条记录变为不可用后的对照 |
| --- | --- | --- | --- |
| 两家供应商，共用一个加工点 | 产线买同一物料，两家供应商都足以独立供量。追到二级加工，两家都只走 MILL-9。该点停工会同时打断两条路径。 | 第二家改走独立加工点 MILL-4，当前记录支持解除这项共同加工点风险。 | 第二家的加工点无法核实，不能确认两路独立。 |
| 复产动作互相等 | 站点只能靠 X 复产，X 等 Y、Y 等 Z、Z 又等 X，三步都未完成。按当前流程无法启动。 | Z 改为等待已通过的独立检查，链条可以启动。 | Z 的前置记录缺失，不能确认流程是否卡死。 |
| 审批人与发起人账号不同，授权同源 | 付款发起和审批必须来自不同责任单位。申请账号与代理审批账号不同，沿各自授权链都落到 UNIT-M。 | 审批权改由 UNIT-N 授出，当前授权符合分离规则。 | 审批人的授权来源未入库，不能判断是否合规。 |

三种结构分别需要识别共享依赖、闭环阻塞、授权同源。第一种有现实背景，英国政府对供应链韧性的研究把多层供应商可见性和依赖集中列为分析要素。这里的产线和对象编号均为合成。已有 GraphQA 用不同的自然语言编码和图结构测模型的图推理，本实验借鉴了结构对照，换成营业场景与来源核验。 [英国政府供应链研究](https://www.gov.uk/government/publications/global-supply-chains-a-foresight-report-on-risk-and-resilience/global-supply-chains-a-foresight-report-on-risk-and-resilience) · [Google Research GraphQA](https://research.google/blog/talk-like-a-graph-encoding-graphs-for-large-language-models/) · [核心记录](core-cards.json)

## 对照怎么做

- 每类三种状态，有隐患、在所查范围内未发现这项隐患、证据不足。题面保持相同，只改一条关系或其可用性。三类 × 三态 × 两档目录规模共 18 个场景，每组每场景两次。同一个 DeepSeek Flash 共发起 108 次独立调用。
- 同一套事实一边渲染成带链接的 README 说明块，一边保留带类型的关系索引。小目录 35 张，大目录 755 张。同类干扰项使用相近对象名称和相同业务词汇，属于不相关对象。
- 全文组读完整目录。关键词组对同一 README 单次 BM25，最多取十张说明。对象组从题中给定 ID 出发，顺向走最多四跳、取至多十张说明。最终三组都读原始 Markdown 记录。各组不预先读风险标签，运行时没有调用检测器。对象组测的是实体锚定后的按需拼接证据。
- 原样保留模型的分类、关系编号和解释。宽松分只判风险状态；严格分还要求正确的关键对象、不捏造对象，并能指出影响判断的全部四条记录。缺失的记录应明确指出。把关系编号重复放进对象栏会失去严格分，即使解释正确。跨三态都通过用于核验稳定性。
- 加了一个等价性检查。程序从 Markdown 解析编号链接，再从同一对象按同一跳数走，18 个场景都选出和对象索引相同的原文。相同链接与同一检索算法可以通过 README 提供同样的模型输入。这项检查无需再重复调用模型。 [试验协议](protocol.md) · [检索及判分](run.py)

## 实际结果

| 目录 | 路径 | 仅结论正确／18 | 结论与证据均合格／18 | 平均输入 token |
| --- | --- | ---: | ---: | ---: |
| 35 张 | 全文 README | 13 | 9 | 1,407 |
| 35 张 | README 单次关键词 | 6 | 0 | 641 |
| 35 张 | 对象路径检索 | 16 | 15 | 316 |
| 755 张 | 全文 README | 10 | 6 | 27,375 |
| 755 张 | README 单次关键词 | 6 | 0 | 828 |
| 755 张 | 对象路径检索 | 17 | 15 | 316 |

在 755 张资料时，有风险的正例共 6 次，附合法证据的发现是全文 2/6、单次关键词 0/6、对象路径 6/6。全文两次都发现了同源审批，证明能从现有事实推出未写明的隐患。供货正例里，全文两次都说第二家走 MILL-4，真实 S4 指向 MILL-9，因而误报没有问题。对象组两次都给出了真实共同加工点和四条记录。

关键词组经常退回证据不足。大目录没有一次找齐四条必要记录。对象组 18 次都取齐了，仍有一次把独立加工点判成证据不足，另有两次在复产反例的对象栏混入关系编号。正文解释可以看懂，结构化回执仍应当区分对象和关系。此外，全文组有两次解释“不同单位，未见问题”，却把分类填成 risk。可以用这类结果区分检索漏证据、事实用错和输出结构错。 [逐题评分和原始说明](results.json) · [API 原始回包](raw.jsonl)

## 企业里如何验证可迁移性

这个规模只回答“关系结构能否让模型更可靠地找出本次未写好的风险”。同一个模型、三类模板、英文、明确对象 ID，资料允许程序追踪。没测开放式审计、未知对象匹配，或者发明从没人见过的风险类型。

更接近现场的下一组用不同团队准备的匿名业务快照。建模方交付通用对象和关系，独立审计方封存风险证据链、关键边变动、同类无风险与缺失样本。评估者只说“审查这个范围”，从报告中核对风险、受影响对象和可复查的证据，也给审计方认定的新发现留一个单独的验证通道。继续保留带链接、按需查的强 README，才能判断投资图索引、更新关系或改进检索各贡献了多少。
