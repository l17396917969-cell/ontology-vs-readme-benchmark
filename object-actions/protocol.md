# 对象、关系、动作 Schema 与 README · 实验协议

本体操作化定义为运行时可查询的业务 Schema。节点是类型化业务对象，边提供跨系统的关联路径，动作定义参数和受控的读写方式。先用题面的词和别名定位对象与动作候选，再加载对应签名及路径。模型选择动作和参数，由已有函数执行。底层数据继续留在原表。

使用同一套 SQLite 合成数据及 README 内容，24 个业务域，订单、CRM、支付、财务制度、分析宽表、伙伴名册和工单工作流。另加一个只在内存运行的工单动作表。新增 20 题，包含读取、跨源、跨域、缺关系和沙箱写入。每题每组重复两次。四组共享调用模型、输出预算、真实用户问题、可见业务规则和批准口径。

| 对照 | 怎么找到说明 | 怎么执行 |
| --- | --- | --- |
| 整份 README | 全域资料 | 模型提交 SQL |
| 按域查 README | 按题面域名定位并读取该域全部资料 | 模型提交 SQL |
| 按域查 README + 函数 | 同一份按域资料，动作说明也来自共同的 README | 模型挑选函数，工具执行 |
| 对象、关系、动作 Schema | 分词、同义词索引、路径扩展、按需加载少量动作 | 模型挑选同一批函数，工具执行 |

前三列给四种可部署方案，行动执行器配对可估查找方式的影响，按域两组可估执行方式的影响。给 README 这组提供同一套函数，使这项比较能回答维护 Schema 的额外意义。仅比较四个已实现方案。目录中的业务域名明确写在题面，检索器知道目录名称，无需模型先猜域名称。只模拟可控读写，API 中只发送合成描述和题目。

| 指标 | 口径 |
| --- | --- |
| 意图定位 | 关键业务动作、域和参数均与人工答案一致，跨域顺序也要正确。 |
| 实际返回 | 执行响应值与独立 Python 参考运算一致。写入同时比对所有工单的最终状态，拒绝题不得修改任何工单。 |
| 时间 | 含本地定位、API 响应、首个预热 SQLite 快照执行。按并发下的次序随机交错跑，报中位数和第 90 百分位。 |
| 消耗 | API 返回的输入、输出、输入缓存命中 token，报告各组实际观测用量。实际账单取决于服务时段和缓存费率。 |
| 审计 | 每题保存入选的动作或资源、原始模型答卷、执行快照结果和写入前后状态。 |

SQL 读取在连接授权器约束下运行。写入仅在任务创建的练习工单表允许更新状态，只有一个语句。函数处理层对当前调用者身份、审批和状态作判定；当前调用者由可信运行参数传入。自由 SQL 组在同样的只读题与写入题上可据共有规则拒绝；若错误写入，依独立快照判失败。不会接触真实企业系统。

## 定位动作接口问题后的复验

原对照完成后冻结结果。两个函数组使用相同动作时，部分模型调用会在 args 里重复 brand 字段；还没到实际的业务函数就被拒绝。另跑一轮，仅重跑这两个函数组，使用服务方原生 strict 工具调用。brand 在签名中仅定义一次，函数的所有参数由 JSON Schema 限定，动作暴露逻辑、数据、题目、两次采样和结果判分维持原样。原对照与这一轮分别报告。同轮主要对照仍为按域读取资料与对象图选用动作。
